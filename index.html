How I run a programme

Four habits behind every delivery

Find what can’t move

A law, a date, an audit, a budget. Plan around the fixed points first — on one programme the fixed point was an Act of Parliament.

Baseline before build

Requirements signed before sprint one, then formal change control. Scope that doesn’t drift is what makes a date credible.

Run in parallel, decide in writing

A named owner for every dependency, weekly reporting, and each trade-off written down so the client chooses knowing both sides.

Measure outcomes

Cycle time, uptime, margin, adoption. “Delivered on time” is a milestone, not a result.
